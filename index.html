STEP 01

获取源码仓库

从 GitHub 克隆源码至本地任意目录，所有文件均以纯原生无 BOM UTF-8 保存。

git clone https://github.com/wakusei0413/BetterBrowse.git
STEP 02

在 Chrome 打开 chrome://extensions，开启右上角「开发者模式」，点击「加载已解压的扩展程序」，选择本项目的 BetterBrowse/ 目录。

QUESTIONS & ANSWERS

常见问题解答

涵盖数据安全性、性能开销、同步机制与 AI 集成常见疑问。

使用 BetterBrowse 会降低浏览器速度或占用大量内存吗？
绝不会。恰恰相反，BetterBrowse 采用极其严苛的资源策略：内容脚本在 auto 模式下完全休眠，不挂载任何昂贵的 DOM 监听器；后台 Service Worker 原生 ESM 驱动随用随唤醒；标签收纳至 IndexedDB 主库后，闲置页面占用的数百兆乃至数 G 内存瞬间释放给操作系统。
表单输入保护（FormGuardRule）是如何保证我没提交的数据不丢失的？
在触发收纳动作前，规则引擎会聚合页面顶层和所有 iframe 框架进行深度探测：一旦检测到任何处于焦点状态或存在已修改未保存文本的 input、textarea 或 contenteditable 元素，立即赋予 P0 级不可侵犯的硬性保留权限，即使阶梯式降级收纳也绝不关闭该标签。
WebDAV 同步真的不会泄露我的账户密码吗？
是的。项目在架构层面推行凭据物理隔离原则：WebDAV 账号与密码存储在专门的不可导出本地仓储中，它被显式排除在 Outbox 操作流、快照文件生成以及任何全量导出备份之外；甚至在 AI 桥接的响应序列化出口处，也有专门的正则过滤器强制拦截任何包含凭据字段的响应。
AI Native 桥接需要常驻运行额外的后台守护进程吗？
完全不需要。根据 Chrome Native Messaging 机制，本机宿主仅由 Chrome 浏览器在扩展需要时按需拉起；当浏览器关闭或客户端断开连接时，宿主会自动清理临时凭据并静默退出，不会占用任何后台驻留内存。
