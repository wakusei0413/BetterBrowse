# 阶段三：AI Skill 与本机 Python 服务（延后，建议降级）

> 配套总览见 [00-overview.md](./00-overview.md)。本阶段**默认延后**，且建议从"常驻 Python 服务"降级为"JSON 导出 + 命令式查询"。

## 1. 原始目标

- 让 AI 通过 Skill 查询并安全修改本地收纳数据；
- 通过本机 Python 服务暴露声明式原子批次接口；
- 不打包 Python 运行时，依赖用户系统已安装；三平台提供诊断。

## 2. 降级建议（推荐）

常驻本机 HTTP 服务（随机端口 + 令牌 + 三平台诊断 + 崩溃恢复）安全面与交付成本过高，对普通 Chrome 扩展用户门槛极大。建议：

- **改用 JSON 导出 + 命令式查询**：后台直接把本地数据导出为标准 JSON 供 Skill 消费，或通过消息总线提供只读/受控写接口，而非常驻 HTTP 服务；
- 若确有"AI 需要写回"的需求，提供**显式、用户触发的导出/导入**，而非常驻监听端口。

## 3. 仅当坚持原方案时需补齐的设计

1. **监听生命周期**：Service Worker 休眠时 socket 断开重连策略；MV3 需 `host_permissions` 包含 `http://localhost` / `http://127.0.0.1`；
2. **安全面**：随机端口选择、一次性令牌的存储与吊销、端口被占用/被探测的应对；三平台（Win/macOS/Linux）诊断与权限文件差异；
3. **权限边界**：AI 可对哪些实体做哪些操作（白名单），凭据字段一律不可经此通道读写；
4. **原子批次**：批次的格式、回滚、与本地队列的串行化关系（复用 `01-local-indexeddb.md` 的连接与并发管理）。

## 4. 验收（若实施）

- 凭据字段不出现在任何 Skill 可访问的接口响应中；
- 单批次操作要么全成功要么全回滚；
- Service Worker 休眠唤醒后能正确恢复连接（或提示用户手动启动服务）。
